# Mission

Trey requested VPS capacity readings and an alarm at 10% remaining, initially clarified hard-drive storage, then explicitly widened scope on 2026-09-28: "Both disk and RAM". Install a host-only 90%-used disk/RAM alarm using the existing ntfy destination. No bot modification/restart, deletion, auto-cleanup or automatic stop. Existing standing approval covers the completed atomic commit/push; this request authorizes activation of this capacity notification timer only.

Implementation: scripts/vps-disk-alarm.js and two scripts/systemd/ogz-disk-alarm unit templates (names retained from the uninstalled disk-only candidate). Check the root filesystem and host RAM every minute; send maximum-priority ntfy on entry into each critical condition, repeat every fifteen minutes while it persists, re-arm independently on recovery. Disk threshold uses used blocks plus non-root available blocks, excluding filesystem reserves. RAM threshold uses MemAvailable / MemTotal from /proc/meminfo, not MemFree or swap: reclaimable cache remains available. Explicit test notifications are labeled TEST and do not change real alarm suppression state. These are host notification controls, not trading configuration or bot operating authority.
