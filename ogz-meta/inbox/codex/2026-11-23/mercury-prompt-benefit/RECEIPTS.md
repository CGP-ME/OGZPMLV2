## Executable comparison and claim checks

The existing gap-recovery fixture was rerun through `scripts/test-isolated.py`, first on the pre-repair source and then on the pinned repaired source. Both exited successfully; all nine recorded source hashes in each run match the corresponding Git version. [Commands](behavior-commands.json) and [behavior excerpts](behavior-results.json) preserve the results. The fixture executes real adapter request construction, CandleProcessor recovery/replay and CandleStore against captured native bars with controlled transport, time and timers. It does not place trades or measure profit. No Jest was added or run.

- **Actual original failure:** a response containing only the already-known right boundary leaves two stored boundary candles but deletes the recovery job and reports completion. The repaired source instead reports `range_start_unavailable` and keeps the job pending. A 31-minute delayed retry keeps the original request range and restores three real interior bars, yielding five stored bars. The old source moves the Kraken request window forward and misses those bars. Both prompts caught the first defect; neither independently traced the second mechanism on the old source.
- **After/new claim: anchor-only completeness proves dropped interior candles.** `brokers/AlpacaAdapter.js:683-705` exhausts pagination before `:726-729` publishes coverage. The fresh sparse-range run legitimately completes with zero interior bars; the paginated run follows all four pages. Alpaca documents that an interval without qualifying trades may have no bar, and its historical-bars contract requires following `next_page_token`. A clock-slot count is therefore not a valid substitute for provider coverage. A provider could still omit a real bar while claiming an exhausted result: that remains an unverified external-data risk, not a demonstrated new failure of this repair. Sources: [Alpaca bar semantics](https://docs.alpaca.markets/us/docs/market-data-faq), [historical bars pagination](https://docs.alpaca.markets/us/reference/stockbarsingle-1).
- **After/new claim: missing `count` URL parameter and a lagging cursor cause Kraken's large-gap failure.** Kraken's OHLC API has no count parameter and limits results to recent history. The fresh retention case has a cursor *after* the requested interval; its failure reason is the missing left anchor, `range_start_unavailable`, at `kraken_adapter_simple.js:381-387`. The separate cursor-behind case produces a different reason. Unrecoverable old history and ongoing retry remain real, previously recorded limitations; the review's causal explanation and universal interval-count threshold are not supported. Source: [Kraken OHLC contract](https://docs.kraken.com/api-reference/market-data/get-ohlc-data).
- **After/new claim: retired-owner cancellation is silent data loss and restart cannot recover.** `core/CandleProcessor.js:842-847,1242-1243` emits cancellation when retiring the job; both fresh owner-change cases record `GAP_BACKFILL_CANCELLED` with `session_transition` and reject the late response. That prevents replay into a different owner. The reviewer did not trace restart hydration. The [earlier live activation receipt](../stop2-gap-coverage-identity-activation/RECEIPTS.md) demonstrates 420 native bars hydrated after restart, but does not prove arbitrary old gaps survive beyond provider retention. Neither a universal restart failure nor universal restart recovery is established.
- **Before/new explanation:** `core/CandleProcessor.js` at the old ref `:518-527,1079-1085` retains the later live candle as the history tail; inserted older backfill does not become that tail as the answer asserts. The completion finding remains correct. Actual monetary loss was not measured.
- **After/old wording:** repaired `core/CandleProcessor.js:781-783,829-838` logs the failure, carries its reason into a trace and schedules retry. Returning this explicit failure receipt is not, by itself, a silent swallowed error. Its broader inactive-adapter and provider-trust observations are limitations, not newly demonstrated active-path defects.

The prototype protocol's ground-truth path description uses shorthand. The actual earlier receipt is [the November 22 gap-range packet](../../2026-11-22/stop2-gap-range-coverage/RECEIPTS.md); the fresh execution is stored beside this document. The protocol itself is retained unchanged.
