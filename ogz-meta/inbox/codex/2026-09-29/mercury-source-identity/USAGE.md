# Reviewing a selected candidate

For an atomic staged change amid inherited dirty work, first stage only the authorized change. Pin both identities explicitly:

`candidate=$(git write-tree)`

`node trai_brain/mercury-bridge/ask.js --agentic --max-tokens=7750 --review-ref="$candidate" --review-base=HEAD "Mercury, break my fix."`

The bridge resolves both refs once. It derives the changed target list from their comparison unless changePaths is explicitly supplied. It captures permitted files from Git objects and binds source/search/AST/recheck reads to that captured tree. The run records tree IDs and manifest identity. Explicit git_show history still reads its requested ref, with historical identity.

Ordinary reviews without these flags keep their existing behavior. changePaths alone retains the existing captured-WORKTREE review mode. Neither alone claims a clean staged candidate. Do not pass max-iterations unless Trey sets one for that run.

If the harness implementation itself has inherited dirty edits, the fixture candidate-loader demonstrates how this mission loaded the exact staged implementation without overwriting those files; it is verification instrumentation, not a production launcher.
