# Auxiliary configuration and phantom-caller findings

121/121 leaves in the root-owned auxiliary groups have an explicit source-effect disposition in `auxiliary.coverage.json`. This is source tracing, not a claim that 121 behaviors were exercised. The actual-class probe below exercises one ignored setting and its working comparison control. Source identity is in `source-census.json`.

No production changes, configuration saves, process restarts, broker requests or orders occurred. The three MTF repairs assigned outside this session are excluded.

## Confirmed findings

1. **Pattern-exit configuration does not reach active exit decisions.** The runner constructs `PatternBasedExitModel` (`run-empire-v2.js:737-742`) and passes it to OrderExecutor. Entry/close paths call `startTracking`/`stopTracking` (`core/OrderExecutor.js:4122,4384,5092,5635`). `evaluateExit` has no production caller found (`core/PatternBasedExitModel.js:81`). Enabling the catalog feature or changing its shadow flag does not connect that evaluator. This is a disconnected feature, not permission to delete it.
2. **Eight pattern-exit properties lack even a model property reader:** `minPatternExitConfidence`, `targetConfidenceWeight`, `minTargetAdjustment`, `maxTargetAdjustment`, `stopConfidenceWeight`, `patternTrailWeight`, `reversalPatterns`, `exhaustionThreshold`. They remain under `featureCatalog.PATTERN_EXIT_MODEL.settings`. Reversal names are independently hardcoded at `core/PatternBasedExitModel.js:280-283`. `fixtures/pattern-settings-probe.cjs` invokes the real class: empty and unrelated configured reversal lists still detect the controlled bearish pattern, while raising the actually consumed `minReversalConfidence` changes the result. Receipt: `pattern-settings-probe.json`. This proves the local mismatch, not a trading invocation.
3. **TRAI maximum confidence is passed but unused.** `trai.maxConf` becomes `maxConfidenceOverride` at `run-empire-v2.js:815`; no consumer reads that property. `trai.vetoPower` is a different issue: runner passes it at `:811`, and `core/TRAIDecisionModule.js:43-46` overwrites it with `false` under the existing opinion-only policy. The stored dynamic declaration therefore cannot enable veto. Do not restore veto as a wiring repair. Both are already historical follow-up leads; this audit verifies their persistence.
4. **Trade-intelligence shadow control only changes a startup label.** `misc.tradeIntelligenceShadow` is assigned/logged at `run-empire-v2.js:757-758`; the engine is created at `:747-756`, but no production evaluation caller is present. Its constructor (`core/TradeIntelligenceEngine.js:47-88`) establishes config/cache and logs; it does not self-schedule work. The runner and engine retain hardcoded tuning values for this dormant component. Calling the logged `ACTIVE` label evidence of active trade management would be wrong.
5. **Tier declarations are not proof of execution restrictions.** `tierPolicy` feeds FeatureFlagManager and TierFeatureFlags summaries (`core/FeatureFlagManager.js:72,212,278-298`; `TierFeatureFlags.js:32-81,146-156`; runner `:647-648`). The asset-access, daily-trade-count and leverage-sizing methods have forwarding wrappers but no production trading caller found. These values have summary/helper effects. Whether further enforcement belongs is unresolved; this audit authorizes none.
6. **Standalone proof/diagnostic tools retain environment-owned values.** `scripts/generate-live-proof.js:239-245` labels mode/risk/stop loss from `LIVE_TRADING`, `MAX_RISK_PER_TRADE`, `STOP_LOSS_PERCENT` with literal defaults. `tuning/pipeline-diagnostic.js:37-49` and `tools/trade-validator.js:43-48` also use independent environment tuning. They are separate CLI/diagnostic surfaces, not established active-runner overrides. Their presence prevents a repository-wide claim that every configurable value has one canonical owner. No script was executed.

## Correctly connected or corrected leads

- `features.enableDynamicSizing` actually controls the executor's confidence-based size multiplier (`core/OrderExecutor.js:3116-3126`), despite a separate unused `dynamicPositionSizer` object. Do not call the setting dead because that object is null.
- `features.enableLearning` affects analysis-time learning (`core/TradingLoop.js:2067`) and separately the TRAI startup memory connection (`run-empire-v2.js:825`; `core/trai_core.js:114`). Those are different lifecycle effects.
- **Proof publication is connected.** An initial directory-excluded search was insufficient. The actual runner (`:434`) and executor (`:20`) import `ogz-meta/claudito-logger.js`. That module reads all nine proof-publication leaves (`:376-392`) and uses them in gated publication (`:643-646,654,734`). The census was expanded to include this production module. Current publication is disabled by its owner; no publication was attempted.
- TRAI's request options are carried into its request client (`core/trai_llm_config.js:57-75`; `core/persistent_llm_client.js:113-117,226`). Editable request settings advertise restart (`foundation/ConfigLoader.js:2606-2616`), matching construction capture. Network behavior was not tested.
- `misc.subscriptionTier` labels backtest reports (`core/BacktestRunner.js:494`); a display/report label is not a phantom trading gate.

## Source and runtime separation

The PatternBasedExitModel, FeatureFlagManager, TierFeatureFlags, TRAIDecisionModule, TradeIntelligenceEngine and standalone proof script bytes were checked against HEAD. Runner, loader and executor have unrelated dirty work, so their current line numbers do not imply a clean-tree runtime test. `runtime-observation.json` records a read-only PM2 observation and selected persisted-state fields: the process is online under `PROFILE=paper`, while the saved state has `isTrading=false` with no pause reason/source. This is not permission to resume it and does not prove its in-memory state.

The audit did not assume that inherited behavior was authorized, that an uncalled intended feature should be deleted, or that an existing test approves a restriction.
