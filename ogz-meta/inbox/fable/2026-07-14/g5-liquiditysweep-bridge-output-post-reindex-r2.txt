*The trigger fires on any high‑range candle, even when no failed break occurs.*

**Evidence** – modules/LiquiditySweepDetector.js:293-300.

### 2. TRIGGER → DIRECTION  

*Direction is derived only from the closing price relative to the opening‑box, ignoring wick‑only sweeps.*  

- The code sets `exitSide` only when `c(bar) > box.high` or `c(bar) < box.low` (lines 344‑352). If a candle’s **wick** breaches the box but the close stays inside, `exitSide` remains `null` and the subsequent pattern detection cannot determine a side, causing a missed or wrong vote.  

- Example counter‑example (candle sequence):  

  1. Opening box: high = 100, low = 90 (detected at `building_box`).  
  2. Next candle: high = 105, low = 92, close = 93. The wick exceeds the box, but `c(bar)=93 < 100`, so `exitSide` stays unset (lines 344‑352). The strategy will never generate a bullish reversal signal despite a clear sweep.  

**Evidence** – modules/LiquiditySweepDetector.js:344-352.

### 3. CONFIDENCE MATH  

*Confidence can be forced to the maximum regardless of actual signal quality.*  

- Base confidence starts with `weights.manipCandle` (0.20) and then adds several other weights (lines 423‑427). The default weight set sums to **1.00** (0.20 + 0.15 + 0.15 + 0.25 + 0.25 = 1.00).

**Evidence** – modules/LiquiditySweepDetector.js:423-438 and default weight definitions lines 55‑59.
