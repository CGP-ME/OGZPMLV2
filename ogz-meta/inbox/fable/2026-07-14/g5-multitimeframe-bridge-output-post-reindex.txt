**Verdict:** **incoherent** – the Multi‑Timeframe (MTF) component does not enforce the higher‑time‑frame confluence thesis, can assign the opposite direction, and its confidence mathematics contains dead‑zones and inversion bugs. The exit contract falls back to the generic strategy contract, and several platform‑layer assumptions (pipeline toggle, base‑time‑frame handling, min‑candle thresholds) silently contradict the intended MTF behaviour.

---

### 1. THESIS → TRIGGER  
**Claim:** The implementation votes even when only lower‑time‑frame data are ready, violating the “higher‑time‑frame evidence must be real and ready” thesis.

* **Ready‑time‑frame tracking** – `MultiTimeframeAdapter.readyTimeframes` is populated as soon as a timeframe reaches `minCandlesForAnalysis` (lines 176‑179).  
* **Confluence scoring** – `getConfluenceScore()` aggregates signals from **all** `readyTimeframes` (lines 736‑739) without checking whether the configured higher‑time‑frames are present.  
* **Orchestrator MTF entry** – `_getMtfConfluenceForEvaluation()` only checks `this.minCandlesMTF` (line 701) and then calls `scopedMtfAdapter.getConfluenceScore()` (line 812). No guard exists for the `requireHigherTFReady` list defined in the config (lines 1779‑1785).  

**Result:** If only the base timeframe (e.g., `15m`) has enough candles, the MTF adaptor will still produce a non‑null confluence score and the orchestrator will forward it (line 1635‑1636). This directly breaks the thesis.

---

### 2. TRIGGER → DIRECTION  
**Claim:** Direction assignment can be wrong for a given market state.

* **Signal composition** – per‑timeframe `signal` is the sum of RSI, trend, MACD and Bollinger contributions (lines 754‑791).  
* **Direction mapping** – the final `direction` is set to `'bullish'` when `signal > 0.15`, `'bearish'` when `signal < -0.15`, otherwise `'neutral'` (lines 1646‑1642).  

**Counter‑example:**  
  * Assume a 15‑minute timeframe where RSI is strongly bullish (`+0.4`), MACD is bullish (`+0.2`), but the trend indicator is strongly bearish (`trendStrength = 1`, `trend = 'bearish'` → `-0.3`).  
  * `signal = 0.4 + 0.2 - 0.3 = 0.3` → direction `'bullish'`.  
  * The market, however, is in a clear bearish trend (trend indicator should dominate). The weight for trend (`0.3`) is insufficient to overturn the RSI‑MACD bias, producing a **wrong side vote**.  

The same logic applies in reverse, yielding an opposite‑side vote when bearish MACD and RSI are outweighed by a weak trend signal.

---

### 3. CONFIDENCE MATH  
**Claim:** Confidence is not always a monotonic function of confluence; dead‑zones and inversion exist.

* **Agreement ratio** – `agreementRatio` = `max(bullishCount, bearishCount) / (bullishCount + bearishCount + neutralCount)` (line 425). If all timeframes are neutral, the denominator is non‑zero but the numerator is zero, yielding `0`.  
* **Trend alignment** – `trendAlignment = trendMatches / trendTotal` (line 417). `trendTotal` is incremented only when a non‑null `ind.trend` exists **and** a `primaryTrend` has been set (lines 393‑395). If the first active timeframe is neutral, `primaryTrend` stays `null`, causing `trendTotal` to stay `0` and `trendAlignment` to become `NaN` → `confidence = NaN` (line 427).  
* **Score magnitude** – `scoreMagnitude = Math.abs(rawScore)` (line 1626). If `rawScore` is `undefined` because both `confluence.score` and `confluence.confluenceScore` are missing, `scoreMagnitude` becomes `0` (line 1626), causing the strategy to be silently ignored even when higher‑time‑frame data exist.  

These branches create **dead‑zones** (confidence = 0 or NaN) and can **invert** confidence when the primary trend is set from a weak lower‑time‑frame while later higher‑time‑frames disagree (lines 393‑395).

---

### 4. EXIT FIT  
**Claim:** MTF exits do not use the MTF‑specific exit contract.

* **MTF config** – `config/trading.config.json` defines a dedicated `MultiTimeframe` contract with its own stop‑loss, take‑profit, trailing‑stop and hold‑time (lines 1324‑1331).  
* **Orchestrator MTF evaluation** – the MTF strategy returns only `{direction, confidence, reason, signalData}` (lines 1619‑1643). No reference is made to the `MultiTimeframe` contract, nor is any exit geometry computed. Consequently, downstream execution uses the generic “minStrategyConfidence / confluenceMinScore” gating (lines 630‑633) and the platform‑wide exit ladder, not the MTF‑specific geometry.

  * Assume a 15‑minute timeframe where RSI is strongly bullish (`+0.4`), MACD is bullish (`+0.2`), but the trend indicator is strongly bearish (`trendStrength = 1`, `trend = 'bearish'` → `-0.3`).  
  * `signal = 0.4 + 0.2 - 0.3 = 0.3` → direction `'bullish'`.  
  * The market, however, is in a clear bearish trend (trend indicator should dominate). The weight for trend (`0.3`) is insufficient to overturn the RSI‑MACD bias, producing a **wrong side vote**.  

The same logic applies in reverse, yielding an opposite‑side vote when bearish MACD and RSI are outweighed by a weak trend signal.

---

### 3. CONFIDENCE MATH  
**Claim:** Confidence is not always a monotonic function of confluence; dead‑zones and inversion exist.

* **Agreement ratio** – `agreementRatio` = `max(bullishCount, bearishCount) / (bullishCount + bearishCount + neutralCount)` (line 425). If all timeframes are neutral, the denominator is non‑zero but the numerator is zero, yielding `0`.  
* **Trend alignment** – `trendAlignment = trendMatches / trendTotal` (line 417). `trendTotal` is incremented only when a non‑null `ind.trend` exists **and** a `primaryTrend` has been set (lines 393‑395). If the first active timeframe is neutral, `primaryTrend` stays `null`, causing `trendTotal` to stay `0` and `trendAlignment` to become `NaN` → `confidence = NaN` (line 427).  
* **Score magnitude** – `scoreMagnitude = Math.abs(rawScore)` (line 1626). If `rawScore` is `undefined` because both `confluence.score` and `confluence.confluenceScore` are missing, `scoreMagnitude` becomes `0` (line 1626), causing the strategy to be silently ignored even when higher‑time‑frame data exist.  

These branches create **dead‑zones** (confidence = 0 or NaN) and can **invert** confidence when the primary trend is set from a weak lower‑time‑frame while later higher‑time‑frames disagree (lines 393‑395).

---

### 4. EXIT FIT  
**Claim:** MTF exits do not use the MTF‑specific exit contract.

* **MTF config** – `config/trading.config.json` defines a dedicated `MultiTimeframe` contract with its own stop‑loss, take‑profit, trailing‑stop and hold‑time (lines 1324‑1331).  
* **Orchestrator MTF evaluation** – the MTF strategy returns only `{direction, confidence, reason, signalData}` (lines 1619‑1643). No reference is made to the `MultiTimeframe` contract, nor is any exit geometry computed. Consequently, downstream execution uses the generic “minStrategyConfidence / confluenceMinScore” gating (lines 630‑633) and the platform‑wide exit ladder, not the MTF‑specific geometry.
