### 1. THESIS → TRIGGER  

*The thesis* – “a close above the prior Donchian channel high should imply an upside‑breakout continuation” – is **not guaranteed** by the current trigger logic.  

*Implementation* (DonchianBreakout.evaluate) builds the prior channel from all candles **except the current one** (`candles.slice(0, -1)`) and fires a buy signal whenever the **current close is strictly greater** than the prior high:

```js
const channel = IndicatorCalculator.calculateDonchian(candles.slice(0, -1), this.entryPeriod); // 70‑71
if (price > channel.upper) {                     // 80‑81
    const extensionAtr = (price - channel.upper) / atr; // 81‑82
    return this._signal('buy', this._confidence(extensionAtr), stopPct, …); // 84‑87
}
```

*Counter‑example* – a single‑candle spike that closes above the prior high but immediately reverses does **not** satisfy the “continuation” thesis, yet the code will still emit a buy signal. For example:

| candle N‑1 (prior) | channel.upper = 100 |
|-------------------|---------------------|
| candle N (current) | close = 101 (price > upper) → signal emitted (lines 80‑87) |

If candle N+1 closes back at 99, the breakout was a false spike and the thesis is violated while the trigger fires.  

*Missed‑thesis* – the code never triggers on a **close that stays above the prior high for more than one bar** (a stronger continuation signal). A market that satisfies the thesis (price > high for several bars) will be treated the same as a one‑bar spike, so the trigger does not distinguish a robust breakout from a fleeting one.  

**Evidence:** DonchianBreakout.js:70-87 (trigger) and 90‑98 (short side).

### 2. TRIGGER → DIRECTION  

Direction is assigned as `'buy'` when `price > channel.upper` and `'sell'` when `price < channel.lower` (if shorts are allowed). The logic is correct **only** when the `allowShorts` flag matches the platform’s short‑enablement policy.

*Configuration* sets `allowShorts` to **false** (line 1731 of `trading.config.json`). Consequently, the short branch is dead‑code for the current deployment:

**Evidence:** DonchianBreakout.js:90-98 (direction) and trading.config.json:1731 (`allowShorts: false`).

### 3. CONFIDENCE MATH  

The confidence function adds a **fixed base of 0.55** to a term that is capped at 0.30:

```js

    return Math.max(0, Math.min(1, 0.55 + Math.min(0.30, extensionAtr * 0.15))); // 120‑122
}
```

*Consequences*  

* The confidence never drops below **0.55**, even for a negligible breakout (`extensionAtr ≈ 0`).  
* The maximum confidence is **0.85** (`0.55 + 0.30`).  

The platform’s exit‑contract may demand a **higher minimum confidence** (e.g., a strategy‑specific `minConfidence` of 0.9). Although the current `DonchianBreakout` contract sets `minConfidence: null` (line 1371), any future contract that supplies a non‑null value > 0.85 would **always reject** the signal, making the strategy dead‑locked.

*Spec mismatch* – the doctrine requires confidence to **scale with breakout quality**; a flat 0.55 floor creates a “dead‑zone” where low‑quality breakouts are over‑valued.

**Evidence:** DonchianBreakout.js:120-122 (confidence) and trading.config.json:1371 (`minConfidence: null`).
